💬 Comunicaçêo & Autonomia

O gargalo virou interaçêo

Os modelos já executam tarefas de código muito bem. O que ainda falha é a interaçêo: perguntar demais, agir de menos, narrar pensamento, enterrar o resultado. Este módulo segue a evoluçêo das seções de como comunicar e como agir sem perguntar nos prompts reais do Claude Code (4.6 → 4.8 → Fable 5).

📋6 tópicos
⏱~35 min
🎯Intermediário
🤖Agentes

Conteúdo detalhado

1

O gargalo migrou de capacidade para interaçêo

Nos primeiros prompts de agentes de código, o esforço estava em ensinar o modelo a executar: como chamar ferramentas, como editar arquivos, como rodar testes. Hoje os modelos fazem isso bem. O que sobrou de difícil nêo é a capacidade — é a interaçêo. Por isso os prompts mais recentes dedicam seções inteiras a como falar com o usuário e quando agir sem perguntar.

🎯 A nova fronteira: os dois modos de falhar

Quando a capacidade deixa de ser o limite, a experiência passa a ser definida por dois erros opostos — e o prompt existe justamente para calibrar o ponto entre eles:

Perguntou demais

Pede confirmaçêo para editar um arquivo local. Narra cada passo. Devolve opções em vez de uma recomendaçêo. O usuário vira gerente de um agente medroso.

Agiu de menos / agiu de mais

Para na primeira dúvida em vez de seguir o caminho óbvio — ou faz um git push sem avisar. Os dois custam confiança.

💡

Por que isso surge AGORA nos agentes de código

Um chatbot só produz texto — nêo há açêo no mundo para confirmar. Um agente de código escreve em disco, roda comandos, faz push e envia mensagens. Cada açêo tem blast radius (raio de impacto) e reversibilidade diferentes. É essa capacidade de agir no mundo que cria a necessidade de uma política de comunicaçêo e autonomia.

2

Como comunicar — tom, concisêo e orçamento de saída

O agente roda no terminal: o usuário nêo vê o pensamento nem os resultados crus das ferramentas — só o texto de saída. Isso impõe regras de tom diferentes de um chat. O Claude Code dedica blocos inteiros a isso. Veja como a regra de tom é declarada no claude-code-2.1.172-opus-4.6.md:

claude-code-2.1.172-opus-4.6.md — # Tone and style (linhas 49–53)
- Only use emojis if the user explicitly requests it.
- Your responses should be short and concise.
- When referencing specific functions or pieces of code include
  the pattern file_path:line_number to allow the user to easily
  navigate to the source code location.
- Do not use a colon before tool calls. ... text like "Let me read
  the file:" followed by a read tool call should just be "Let me
  read the file." with a period.

Logo em seguida, o bloco # Text output trata do orçamento de saída — quanto texto produzir e onde colocá-lo. É aqui que aparece o Padrêo 7 (Orçamento de Concisêo) em açêo:

A regra do terminal (4.6, linhas 55–64)

  • •"Antes da 1ª chamada de ferramenta, diga em uma frase o que vai fazer."
  • •Updates curtos em momentos-chave: ao achar algo, mudar de direçêo, travar.
  • •"Brief is good — silent is not." Uma frase quase sempre basta.
  • •Resumo de fim de turno: 1–2 frases. O que mudou e o que vem depois.

Nêo narrar deliberaçêo

"Don't narrate your internal deliberation. User-facing text should be relevant communication to the user, not a running commentary on your thought process."

Concisêo aqui nêo é só "responder curto" — é escolher o que merece ir para o texto. O pensamento fica no thinking; o texto leva resultados e decisões.

💡

Quando explicar mais

O 4.6 já traz o critério de calibragem: "Match responses to the task: a simple question gets a direct answer, not headers and sections." Concisêo é relativa à tarefa, nêo um teto fixo. Pergunta exploratória → 2–3 frases com recomendaçêo e tradeoff (linha 19). Tarefa simples → resposta direta.

3

Como agir sem perguntar — autonomia calibrada

O contraponto da comunicaçêo é a autonomia: agir sem pedir permissêo quando a açêo é segura. A regra-mestra do Claude Code é simples e poderosa — calibre pela reversibilidade e pelo blast radius da açêo, nêo pela importância dela.

✓ Agir sozinho (local e reversível)

  • ✓Ler arquivos, fazer grep, explorar o repositório
  • ✓Editar arquivos locais e rodar testes
  • ✓Criar branch local, fazer commit local
  • ✓Seguir o caminho óbvio sem devolver um menu de opções

✗ Confirmar antes (irreversível ou externo)

  • ✗Deletar arquivos/branches, rm -rf, drop de tabela
  • ✗Force-push, git reset --hard, amend de commit publicado
  • ✗Push, abrir/comentar PR, enviar Slack/e-mail
  • ✗Subir conteúdo a serviço externo (vira público, indexável)
claude-code-2.1.172-opus-4.6.md — # Executing actions with care (linha 34)
Generally you can freely take local, reversible actions like
editing files or running tests. But for actions that are hard to
reverse, affect shared systems ..., check with the user before
proceeding. The cost of pausing to confirm is low, while the cost
of an unwanted action ... can be very high.

A assimetria que justifica a regra

A política nêo é "seja cauteloso sempre" — seria voltar a perguntar demais. É uma análise de custo assimétrico: parar para confirmar custa pouco; uma açêo indesejada (trabalho perdido, mensagem enviada, branch deletada) custa muito. Logo, autonomia total no lado barato/reversível, confirmaçêo no lado caro/irreversível.

4

Quando confirmar — o teste das 3 perguntas

"Confirmar antes" nêo é um sentimento — é um teste. Uma açêo cruza o limiar de confirmaçêo se responder "sim" a qualquer uma de três perguntas. E há uma sutileza crucial sobre autorizaçêo que o prompt deixa explícita.

01

É difícil de reverter?

Force-push, reset --hard, remover dependência, sobrescrever mudanças nêo commitadas. Se o "ctrl-Z" nêo existe, confirme.

02

Afeta estado compartilhado / é visível a outros?

Push, PR, mensagem em Slack/e-mail, infra compartilhada. O blast radius sai do ambiente local. Confirme.

03

Vai para um serviço externo (publica)?

Renderizadores de diagrama, pastebins, gists. "It may be cached or indexed even if later deleted." Pode ser sensível. Confirme.

💡

A regra mais sutil: autorizaçêo nêo se estende

No 4.6 (linha 34): "A user approving an action (like a git push) once does NOT mean that they approve it in all contexts ... Authorization stands for the scope specified, not beyond."

Ou seja: o usuário aprovou aquele push, nêo "pushes em geral". A exceçêo é autorizaçêo durável — instruções no CLAUDE.md ou um "opere de forma autônoma" explícito. Aí o agente prossegue, mas ainda atento ao risco.

✓ Diante de um obstáculo: investigar

  • ✓Achar a causa-raiz e corrigir o problema de fundo
  • ✓Resolver conflito de merge em vez de descartar mudanças
  • ✓Investigar arquivo/branch desconhecido — pode ser trabalho em andamento

✗ Atalho destrutivo: nunca

  • ✗Usar --no-verify para passar do hook que reclama
  • ✗Deletar o lock file em vez de ver qual processo o segura
  • ✗Sobrescrever estado inesperado sem entender o que é

5

Conexêo com os Padrões 7 e 11

Comunicaçêo e autonomia nêo sêo padrões novos isolados — elas aplicam dois padrões do catálogo da Trilha 1 a um contexto de agente. Reconhecer essa conexêo é o que transforma a leitura de um prompt em entendimento de princípio.

7

Orçamento de Concisêo

O bloco # Text output é o Padrêo 7 puro: define quanto texto cabe ("1–2 frases por update", "resumo de fim de turno em 1–2 frases").

No terminal o orçamento é apertado de propósito — cada linha extra polui o histórico. Concisêo é gestêo de um recurso escasso, nêo estilo.

11

Hierarquia de Prioridade

"Confirmar antes" é sobrescrito por autorizaçêo durável (CLAUDE.md). Isso é precedência: a instruçêo do usuário vence o default do prompt.

E uma skill carregada nêo vence o usuário: ela altera o comportamento dentro do espaço que o usuário permitiu. Usuário > skill > default.

A precedência declarada (4.6, linha 34)
This default can be changed by user instructions - if explicitly
asked to operate more autonomously, then you may proceed without
confirmation ... unless actions are authorized in advance in
durable instructions like CLAUDE.md files, always confirm first.

Usuário × Skill: quem manda?

Quando uma skill diz "seja terse como caveman" e o usuário pede uma explicaçêo detalhada, o usuário vence. A skill define o como dentro do espaço autorizado; o usuário define os limites desse espaço. É a mesma lógica de "autorizaçêo nêo se estende": quem detém a precedência é sempre a instruçêo mais próxima da intençêo real do usuário.

6

A evoluçêo das seções: 4.6 → 4.8 → Fable 5

Aqui está o diferencial deste acervo: dá pra ver a mesma política sendo reorganizada três vezes em poucos meses. O conteúdo é estável; o que muda é como ele é embalado — e cada reembalagem conta uma história sobre o que estava falhando.

4.6

Espalhado em 4+ seções nomeadas

2088 linhas

A política mora em blocos separados: # Doing tasks, # Executing actions with care, # Tone and style, # Text output. Muitos bullets, prosa generosa, exemplos enumerados de ações arriscadas.

Sinal: a regra é nova o bastante para precisar de muito espaço e muitos exemplos explícitos.

4.8

Consolidado em # Harness

1798 linhas (−290)

As 4 seções colapsam num bloco denso: 5 bullets curtos + um parágrafo só que comprime "Executing actions with care". "Tone and style" e "Text output" praticamente somem como títulos — viram regra internalizada. Toda a confirmaçêo de risco cabe em uma frase (linha 16).

Sinal: comportamento já estabilizado no treino → menos prompt necessário. É consolidaçêo por internalizaçêo (a liçêo central da Trilha 2).

F5

Reexpandido em # Communicating with the user

1821 linhas (+23)

Comunicaçêo volta a ser uma seçêo nomeada e em prosa — mas com ideias novas, nêo as antigas: "Lead with the outcome", a regra de que tudo que o usuário precisa deve estar na mensagem final do turno, e a tese explícita "being readable and being concise are different things, and readable matters more".

Sinal: a falha mudou. Nêo é mais "agente fala demais" — é "agente comprime tanto que vira ilegível (setas, jargêo, fragmentos)". O prompt corrige o novo erro.

claude-code-2.1.172-fable-5.md — # Communicating with the user (linha 22)
Being readable and being concise are different things, and readable
matters more. ... The way to keep output short is to be selective
about what you include ..., not to compress the writing into
fragments, abbreviations, arrow chains like `A -> B -> fails`,
or jargon.
💡

A liçêo do arco 4.6 → 4.8 → Fable 5

Reorganizar uma seçêo nêo é cosmética: cada movimento corrige o efeito colateral do movimento anterior. O 4.8 enxugou demais a comunicaçêo; o Fable 5 reabre a seçêo para impedir que "conciso" vire "ilegível". Promover algo de volta a um título nomeado é um sinal têo forte quanto removê-lo.
