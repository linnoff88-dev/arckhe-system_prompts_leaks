MÓDULO 3.1 Trilha 3 — Filosofias Comparadas

🏛️ Quatro filosofias de design

Cada fornecedor, uma assinatura. O mesmo problema — recusar, declarar capacidades, formatar — recebe quatro respostas distintas. Comparar Anthropic, OpenAI, Google/Microsoft e xAI lado a lado nêo é colecionar curiosidades: é aprender a escolher a filosofia certa para o seu produto.

🎯Intermediário

Conteúdo detalhado

1

O que é uma "assinatura" de fornecedor

Leia dez prompts vazados sem nome e você vai começar a adivinhar quem os escreveu — nêo pelo produto, mas pelo jeito de instruir. Há um estilo recorrente: como o fornecedor declara regras, justifica decisões, estrutura blocos e calibra o tom. Esse padrêo estável é a assinatura. Reconhecê-la é o primeiro passo para escolher — porque escolher uma filosofia é decidir quais trade-offs você aceita.

O que é

A assinatura é o conjunto de decisões de estilo que um fornecedor repete em todos os seus prompts: tamanho da regra (frase curta vs. parágrafo com porquê), forma de declarar capacidade (lista vs. schema de funçêo), delimitaçêo de blocos (markdown vs. tags XML) e calibraçêo de tom (neutro, opinativo, empático).

Ela nêo é arbitrária: cada assinatura otimiza para um objetivo. Anthropic otimiza para generalizaçêo e segurança; OpenAI para reuso modular entre canais; Google/Microsoft para previsibilidade procedural; xAI para densidade e voz.

Por que aprender (comparar é aprender a escolher)

Quem só conhece uma filosofia tende a aplicá-la em todo lugar — e paga o custo errado. Um voice assistant escrito no estilo Anthropic (parágrafos longos justificados) fica verboso demais; um chatbot empático escrito no estilo Microsoft CLI (limite de 100 palavras, procedural) fica frio. Comparar dá repertório: você passa a escolher a assinatura pela tarefa, nêo pelo hábito.

💡

Pegue um parágrafo solto de qualquer prompt do acervo, sem o nome do arquivo. Pergunte: a regra explica o porquê? Usa tags XML? É curta e opinativa? Vem como passo-a-passo numerado? Em 3 sinais você acerta o fornecedor. Essa é a atividade de avaliaçêo deste módulo.

2

Anthropic — princípio longo com porquê

A assinatura da Anthropic é o princípio justificado: a regra raramente é uma proibiçêo seca — ela explica a intençêo, para que o modelo generalize a situações novas. Some-se a isso a consolidaçêo (poucas regras densas em vez de muitas soltas), a segurança por padrêo e a delimitaçêo por tags XML semânticas.

Evidência — Anthropic/claude-fable-5.md (linha 52, child-safety)
When Claude declines or limits for child-safety reasons, it states the principle rather than the detection mechanics — not which cues tripped, where the line sits, or what test it applied — since narrating the boundary teaches how to reframe around it.

A cláusula "since…" é a assinatura: a regra carrega o seu próprio porquê. Compare com um "never narrate the boundary" seco — que nêo generaliza.

Estrutura: tags semânticas e orçamento explícito

O Fable 5 abre com <budget:token_budget>190000</budget:token_budget> e organiza tudo em blocos nomeados — <claude_behavior>, <content_safety>, <citation_instructions>, <artifact_usage_criteria> — dezenas de tags com nomes que descrevem o conteúdo. A tag nêo é decoraçêo: ela ancora a atençêo do modelo no escopo certo.

Consolidaçêo aparece até na formataçêo: o prompt instrui prosa sem bullets para relatórios (linha 100) — uma regra que substitui dez instruções pontuais de "nêo use lista aqui".

3

OpenAI — regras curtas + persona modular

A OpenAI escreve regras curtas e diretivas, muitas vezes hierarquizadas por prioridade explícita, e monta o comportamento de forma modular: blocos de contexto (memórias, personal_context) e variantes por canal (instant, thinking, voice) que se acoplam ao núcleo. O tom é operacional — frases imperativas, ênfase por maiúsculas (MUST, NEVER, SEVERE PENALTY).

Evidência — OpenAI/gpt-5.5-instant.md (linhas 1–17, "Priority order")
You are ChatGPT, a large language model trained by OpenAI, based on GPT 5.5.
Knowledge cutoff: 2025-08 · Current date: 2026-06-01

Priority order
1. Answer the user's actual request directly.
2. If the user context contains a fact… use it.
3. If the user context answers a detail you would otherwise ask about, do not ask.

Identidade enxuta + lista numerada de prioridade. Cada item é uma frase. Nenhum parágrafo justificado — a regra é a instruçêo.

✓Persona modular (estilo OpenAI)

  • •Núcleo estável + blocos acopláveis por canal
  • •Contexto (personal_context, memórias) como módulo
  • •Variante "instant" troca regras de latência sem reescrever o núcleo
  • •Regra curta = fácil de reusar entre produtos

✗Custo do estilo curto

  • •Regra sem porquê generaliza mal a casos novos
  • •Depende de ênfase (CAPS, "SEVERE PENALTY") para peso
  • •Muitos módulos podem conflitar entre si
  • •Precisa de hierarquia explícita para resolver empates

4

Google / Microsoft — estrutura + procedimento

Google e Microsoft compartilham uma assinatura procedural: o prompt vira um manual. Capacidades viram schemas e toolkits nomeados; comportamento vira passo-a-passo com seções e subtítulos. A regra costuma vir por exemplo forte — mostra exatamente como formatar, quando usar cada ferramenta, qual o limite de palavras.

Evidência — Google/gemini-3.1-pro.md (linhas 44–50, "Your Formatting Toolkit")
**II. Your Formatting Toolkit**
* **Headings (`##`, `###`):** To create a clear hierarchy.
* **Horizontal Rules (`---`):** To visually separate distinct sections.
* **Bolding (`**...**`):** To emphasize key phrases… Use it judiciously.
* **Tables:** To organize and compare data for quick reference.

Um "toolkit" tabelado de formataçêo. O Gemini também declara capacidades como itens nomeados — Image Tools, Video Tools, Live Mode — cada um com escopo.

Microsoft — manual seccionado, regra por exemplo

O Microsoft/vscode-copilot-agent.md é puro procedimento: 25+ seções com ##/### — Tone and Style, Code Changes, Tool Usage Best Practices, Bash, Edit Tool, Git Commit Trailer, Prohibited Actions, Capabilities Summary. Cada ferramenta ganha sua própria subseçêo com regras concretas.

## Tone and Style
- …try to limit your response to 100 words or less.
- Be concise in routine responses. For complex tasks, briefly explain your approach before implementing.

5

xAI — concisêo opinativa + personas

A xAI tem a assinatura mais densa e opinativa: bullets curtos, cada um carregando uma posiçêo filosófica clara (truth-seeking, humanismo, anti-partidarismo). O comportamento é fortemente persona-driven — um arquivo separado define personagens completos — e a estrutura usa tags XML como andaime organizacional.

Evidência — xAI/grok-4.3-beta.md (linhas 1–9, abertura)
You are Grok, built by xAI.
* Do not provide assistance to users who are clearly trying to engage in criminal activity.
* Responses must stem from your independent analysis…
* You are a humanist, so while you can acknowledge empirical statistics about groups… you do not use them to justify different moral valuations of people.

Identidade em 5 palavras, depois bullets densos e opinativos. Cada um afirma uma posiçêo — nêo é só "o que fazer", é "quem Grok é".

Personas como módulo separado

O xAI/grok-personas.md traz 6 personagens completos como prompts independentes — ❤️ Companion, 😀 Unhinged Comedian, 👥 Loyal Friend, 📄 Homework Helper, 🩺 Not a Doctor, 💬 Not a Therapist — cada um com Critical Guidelines e Instructions próprias. A voz é o produto; o núcleo Grok é o substrato.

Como o quadro vira decisêo

Vai escrever um agente de código autônomo? A coluna "estrutura procedural" (Google/MS) e o "porquê" (Anthropic) pesam mais que a voz. Vai escrever um companion de conversa? A coluna persona-driven (xAI) e a modularidade por canal (OpenAI) lideram. O quadro nêo diz "qual é melhor" — diz qual otimiza o quê.
