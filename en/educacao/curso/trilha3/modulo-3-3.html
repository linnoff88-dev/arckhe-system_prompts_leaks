MODULE 3.3 Track 3 — Comparative Philosophies

📊 Comparison matrix

One problem, four answers. Take three universal prompt design problems— when to refuse, how to cite the source, acting without asking—and see the solutions from four providers side by side. The matrix doesn't say who's "right": it reveals the trade-offs that each choice carries, and becomes a reference tool that concludes Track 3.

Detailed content

1

How to read the matrix

A comparison matrix is the right tool when there are one axis of problems e one axis of solutions. Here the problem goes in the lines and the provider goes in the columns. You read a row to answer “how does each one solve this?” and a column to reconstruct “what is this provider’s signature?” The value isn’t in any one cell—it’s in the contrast what the grid reveals.

What it is

The lines These are universal problems — every product prompt needs to address them, regardless of provider. We chose three that appear in almost every leaked prompt: when to refuse, how to cite the source e when to act without asking.

The columns These are the four philosophies in Module 3.1: Anthropic (principle + why), OpenAI (short rule + persona), Google/Microsoft (structure + procedure), and xAI (opinionated concision + XML). Each cell is a real choice, with a citable source in the collection.

Why learn

Reading prompts in isolation teaches patterns; reading them in a matrix teaches to decide. When you write your own prompt (Track 4) and run into one of these problems, the matrix shows the range of possible responses and the cost of each — you choose consciously, not by blind imitation.

💡

Read in two directions

Row = "how do they solve the same problem?" Column = "what's this provider's signature?" A cell only gains meaning at the intersection—a standalone answer doesn't tell you whether it's good; only the contrast does.

Every prompt defines a behavioral boundary. The question is how this limit is written down: as a justified principle, one short rule, one structural override or a blunt refusal? Each style has a theory of robustness behind it.

Problem B — how to cite the source

When the model has access to external context—files, emails, profiles, web pages—the question arises: where does the truth come from, and how is it referenced? Here the philosophies diverge sharply because each protects something different: the integrity of the source, the downstream channel or the visual richness.

Provider Source / citation rule Evidence in the collection
Anthropic
resource, not requirement		 Treats sources as conversation features (web search, past chats, files) that you can trigger and mention to the user. Focus on transparency, not a rigid citation format. claude-fable-5.md
L33 (settings/features)

Problem C — act without asking

The axis of autonomy: when should the model move ahead without asking permission, and when should it stop and confirm? This is the problem that most distinguishes chatbots of agents — and where each provider’s philosophy is most visible.

5

Trade-offs revealed

Every cell in the matrix has a cost. No choice is free: gaining robustness on one side costs flexibility on the other; gaining autonomy costs predictability. This is the reading that turns the matrix into description in decision tool.

What a prompt design trade-off is

It’s the hidden cost of a rule. A prompt based on principles generalizes better, but costs tokens and requires a model capable of reasoning about intent. A prompt based on procedure is deterministic and auditable, but rigid when faced with new cases. The matrix shows this cost at every intersection.

Choice What you gain What it costs
Principle + rationale
Anthropic		 Generalizes to new cases; robustly resists circumvention; the “why” guides unforeseen situations. More tokens; requires a strong model; less auditable ("why did it refuse here?" has no fixed rule).
Short rule + persona
OpenAI		 Concise and inexpensive; consistent persona; easy to maintain; good for high-volume conversations. A bare rule generalizes poorly; it depends on the persona to "hold" the rest; ambiguous at the edges.
Structure + procedure
Google/MS		 Deterministic and auditable; great for pipelines and agents; fails predictably. Rigid outside the expected path; long; maintenance grows with each new exception.
Concision + XML
xAI		 Lightweight and direct; delegates to the model; clear structure; quick to read and edit. Little explicit coverage; behavior varies more by model; fewer guarantees.

⚠️ The mistake of copying the wrong cell

The danger of the matrix is treating a cell as "the best practice" and applying it out of context. Gemini's procedural refusal is great for a widget pipeline — putting this in a casual chatbot creates a bureaucratic assistant. Grok’s concision is great with a strong model — pasting it into a weaker model leads to unpredictable behavior. The right cell depends on the product, not the provider’s prestige.

How to build your own matrix

The matrix isn’t a fixed artifact — it’s a method. When designing a prompt and deciding on a behavior, build a small matrix for that problem and fill it in with the providers that matter for your use case. Here’s the step-by-step process that wraps up Track 3.

01

Choose universal problems (rows)

List 2–4 behavior decisions that every your domain’s prompt must make. Refusal, citations, and autonomy are a good starting point; add the ones for your product (e.g., "how to handle ambiguity," "when to use Markdown").

02

Choose relevant providers (columns)

Pick 3–5 prompts from the collection that resemble what you want to build. For a coding agent, include vscode-copilot-agent.md; for a chatbot, claude-fable-5.md e gpt-5.5-instant.md.

03

Fill each cell with the evidence

Each cell is a sentence + the citable source (arquivo.md · linha). Without a source, it's not a matrix — it's an opinion. Citing the actual path is what makes the matrix auditable and reusable.

04

Note the trade-off, then decide

For each choice, write down what you gain and what it costs. Only then choose the cell that serves the your product — and take that decision (with the reason) to Track 4, where you build your prompt.
